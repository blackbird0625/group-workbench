# 小组作业工作台 · Group Workbench

一个为小组作业设计的前端协作工作台模板：**任务看板、交付文档（版本管理 + 划线批注）、资料库、公告区、文献汇总（共同审稿）、审议意见**，全部集成在一个页面里。

- 前端：纯 HTML/CSS/JS，无构建步骤、无框架依赖
- 后端：**不附带，按 [API.md](./API.md) 自行对接**（Node.js / Python / 云函数 / Supabase 均可）
- 定制：**第一个打开的人走一遍初始化向导**（像装系统），功能模块、任务分类、权限规则全部点选决定

> 本模板由一个真实的小组课程项目通用化而来。

## 像装系统一样初始化

后端跑起来后，第一个打开页面的人会进入 6 步向导：

1. **基本信息** — 工作台名称、副标题、管理员称呼（组长/队长/负责人随你定）
2. **功能模块** — 勾选需要的功能（资料库 / 公告区 / 文献汇总 / 审议意见；总览和任务看板常驻）
3. **权限设置** — 逐项决定哪些操作仅管理员可用、哪些开放给所有成员（新建任务、验收、发布公告……全部由你定）
4. **任务分类** — 自定义看板分类（颜色自动分配）
5. **资料分类** — 自定义资料库分类
6. **成员与管理员** — 填写成员名单，勾选谁有管理权限（支持多管理员）

每一步都提供**预设方案**可一键套用（如功能模块的「全套 / 极简 / 文献型」、权限的「组长集权 / 民主协作 / 高度自治」、分类的「写作型 / 视频型 / 研究型」），套用后仍可逐项自定义。

初始化只有一次，配置保存在服务端、跟随数据走。之后每位成员首次登录**自己设置 PIN（密码）**——密码权限完全在个人手里，管理员只能重置、不能查看或代设。

## 功能一览

| 模块 | 说明 | 可关闭 |
|---|---|---|
| 总览 | 我的任务、待认领、待处理意见、最新公告 | 核心 |
| 任务看板 | 五状态流转：待认领 → 进行中 → 待审核 →（需返工 ⇄ 进行中）→ 已完成 | 核心 |
| 资料库 | 分类上传文件（限 6MB），大文件建议放网盘贴链接 | ✅ |
| 公告区 | 可置顶的公告（谁能发由权限设置决定） | ✅ |
| 文献汇总 | 提交题目自动查重，全员 👍/👎 投票 + 审稿评论，采纳后一键导出清单 | ✅ |
| 审议意见 | 对任务安排本身的建议，拥有处理权限的人标注采纳/不采纳 | ✅ |
| 使用说明 | 内置操作指引与 FAQ | 核心 |

其他能力：每 12 秒多设备自动同步、DDL/周日进度/待办提醒、全量备份与恢复。

## 使用步骤

### 第 1 步：实现后端

打开 **[API.md](./API.md)**，按说明实现约 30 个 JSON 接口。要点：

- `GET /api/bootstrap` 返回全量状态（含初始化时保存的 settings），前端每 12 秒轮询它实现多设备同步
- 登录凭证走 `X-Session` 头或 Cookie，PIN 需加盐哈希存储
- 权限规则按 `settings.perms` 动态执行——初始化者怎么定的就怎么查，后端不要写死
- 数据模型、每个接口的请求/响应格式、自查清单都在文档里

### 第 2 步：部署后端（三种方案任选）

#### 方案 A：Node.js 自己的服务器（最简单）

适合：有云服务器/宿舍主机，组内使用。

1. 服务器装 Node.js 18+，把仓库传上去
2. 写一个按 API.md 实现的 `server.js`（或自己找参考实现），加静态文件服务指向 `public/`
3. 启动：

```bash
node server.js                    # 前台运行
# 或用 pm2 守护（推荐，关掉终端也能跑）：
npm install -g pm2
pm2 start server.js --name workbench
```

4. 防火墙/安全组放行端口（默认 3000），组员访问 `http://服务器IP:3000`

> 注意：数据存在服务器本地文件里，记得在 `.gitignore` 里排除数据目录，别把组员的 PIN 哈希和上传文件提交进 git。

#### 方案 B：免费托管平台（Render / Railway / Fly.io 等）

适合：没有服务器，白嫖部署。

1. 把前端 + 你实现的后端代码推到一个新仓库（本模板仓库可以直接 fork 后加后端代码）
2. 在平台上传这个仓库，Build Command 留空或 `npm install`（取决于你的后端是否用依赖），Start Command 填你的启动命令（如 `node server.js`）
3. 平台会给一个公网地址（如 `https://xxx.onrender.com`），前端和 `/api` 天然同域，直接用

> 注意免费平台通常有休眠（一段时间没人访问会冷启动变慢）和数据重置（临时文件系统可能被清空）——**务必定期用页面里的「📥 备份」导出 JSON**，或挂平台提供的持久磁盘/数据库。

#### 方案 C：静态托管 + Supabase（全免费）

适合：想用 GitHub Pages / Vercel / Netlify 托管前端，数据库用 Supabase 免费额度。

1. 在 [supabase.com](https://supabase.com) 建项目（免费档够小组用）
2. 按下面的 SQL 建 4 张表（表格里是按 API.md 数据模型拆的；嫌麻烦也可以只建一张 `state` 表存整个 JSON）：

```sql
-- 简化方案：单表存全量状态（推荐起步用）
create table if not exists workbench_state (
  id int primary key default 1,
  data jsonb not null,
  updated_at timestamptz default now()
);
insert into workbench_state (id, data) values (1, '{}')
on conflict (id) do nothing;

-- 或者：拆表方案（并发更稳，工作量更大，按 API.md 模型自建）
-- members / tasks / resources / announcements / literatures / reviews / settings
```

3. 在 Supabase 项目里创建 Edge Functions（或用任何能跑函数的服务），按 API.md 实现接口，读写上面这张表
4. 前端 `fetch('/api/...')` 需要改为指向函数地址（或用 Vercel 的 rewrites 把 `/api` 转发过去），保持同域最省事
5. 前端部署到 GitHub Pages / Vercel / Netlify（`public/` 目录直接传）

> 注意：anon key 虽然是"可公开"的，但 RLS 策略要写对——这套数据模型里 PIN 哈希字段绝不能对 anon 可读，`workbench_state` 表建议只允许函数（service role）访问。

### 第 3 步：开始使用

部署好后把链接发给组员，第一个打开的人完成初始化向导，大家就能多设备协作了。

> 想改默认预设（向导的预填值），编辑 `public/config.js` 即可，无需写代码。

## 注意事项

- 本应用面向小组内部使用，**未做公网级防爬、限流**，请勿在高流量公开场景裸奔；PIN 用于防止组内冒名，不是银行级安全
- 上传的附件以 base64 存在数据里，因此单文件限 6MB；数据量大时可参照 API.md 改为对象存储
- 数据安全靠「备份/恢复」功能，建议定期备份
